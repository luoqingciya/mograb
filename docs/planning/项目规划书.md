# MoGrab 项目规划书

> **项目名称：MoGrab**  
> **项目定位：开源、API-First、可扩展的小说获取与电子书整理工具**  
> **许可证：GNU General Public License v3.0（GPLv3）**  
> **后端：Python**  
> **依赖管理：uv**  
> **分发形态：CLI（Windows / Linux） + Desktop（Windows）**  
> **Desktop：Electron**  
> **核心原则：自定义书源规范，不兼容 Legado，不允许书源直接执行任意 Python 代码**

---

## 1. 项目概述

MoGrab 是一个面向个人阅读与电子书整理场景的开源小说获取工具。

项目不以“兼容尽可能多的历史书源”为主要目标，而是建立一套**干净、严格、可测试、可版本化的 MoGrab Source Specification（书源规范）**，通过统一的 Source Engine 获取书籍、目录和正文，再利用任务系统完成下载、增量更新、缓存、重试与导出。

MoGrab 采用 **API-First** 架构：

```text
                    ┌────────────────────┐
                    │   Electron Desktop │
                    │      Windows       │
                    └─────────┬──────────┘
                              │ REST API
                              ▼
┌────────────────────────────────────────────────────┐
│                  MoGrab API Server                 │
│                      FastAPI                       │
├────────────────────────────────────────────────────┤
│ Source │ Search │ Book │ Task │ Download │ Export │
├────────────────────────────────────────────────────┤
│              MoGrab Core Engine                    │
├────────────────────────────────────────────────────┤
│ HTTP │ Cache │ Parser │ Transformer │ Storage      │
└────────────────────────┬───────────────────────────┘
                         │
                   ┌─────▼─────┐
                   │  SQLite   │
                   └───────────┘
```

CLI 与 Desktop 不应该各自实现业务逻辑，而应该围绕 Core / API 工作。

---

# 2. 产品目标

## 2.1 核心目标

MoGrab 第一阶段需要解决以下问题：

1. 从可配置书源中搜索小说。
2. 获取小说元数据。
3. 获取章节目录。
4. 下载章节正文。
5. 清洗和规范化正文。
6. 保存本地书籍数据。
7. 导出 TXT、EPUB、Markdown 等格式。
8. 支持失败重试、暂停、继续和取消。
9. 支持小说增量更新。
10. 书源可以独立开发、测试、升级。
11. CLI 与 Desktop 使用同一套核心能力。
12. 所有核心 HTTP API 有明确版本。

## 2.2 非目标

第一版明确不追求：

- 兼容 Legado 全部规则。
- 任意第三方脚本执行。
- 复杂反爬绕过。
- 验证码破解。
- 付费墙或访问控制绕过。
- 服务器多用户平台。
- 移动端。
- 大规模分布式爬虫。

MoGrab 是**个人工具 / 开源工具**，不是通用爬虫平台。

# 3. 核心设计原则

## 3.1 API-First

所有正式功能必须先进入 Core/API 层，再由 CLI/Desktop 使用。

禁止：

```text
Desktop → 自己写下载逻辑
CLI     → 自己写下载逻辑
```

正确结构：

```text
Desktop ─┐
         ├── API / Core ── Source Engine
CLI ─────┘               ├─ Task Engine
                         ├─ Download Engine
                         └─ Export Engine
```

---

## 3.2 Source-First

MoGrab 的核心竞争力不是“下载按钮”，而是稳定、干净的书源系统。

书源负责描述：

```text
请求什么
从哪里取
如何提取
如何转换
```

而不负责：

```text
重试
并发
缓存
任务调度
数据库
日志
```

这些由 MoGrab Core 完成。

---

## 3.3 声明式书源

MoGrab Source 第一版采用声明式 DSL。

推荐：

```text
YAML Source
   ↓
Schema Validation
   ↓
Source AST / Internal Model
   ↓
Source Engine
   ↓
Book / Chapter
```

书源不是 Python 插件，而是一份经过严格校验的配置。

---

## 3.4 核心模型稳定，外围可替换

例如：

```text
HTTP Client       可替换
HTML Parser       可替换
Database          可替换
Exporter          可扩展
CLI               可替换
Desktop           可替换
```

但是：

```text
Book
Chapter
Source
Task
```

这些领域模型应该尽量稳定。

# 7. Source Specification v1

建议书源由以下部分组成：

```text
Source
├── manifest
├── capabilities
├── search
├── book
├── chapters
├── content
└── transforms
```

示例：

```yaml
version: 1

id: example
name: Example
version_name: 1.0.0
homepage: https://example.com

capabilities:
  - search
  - book
  - chapters
  - content

search:
  request:
    method: GET
    url: https://example.com/search
    query:
      q: "{{keyword}}"

  response:
    format: html

  result:
    list: ".book-item"

    fields:
      title: ".title"
      author: ".author"
      url: "a@href"

book:
  request:
    method: GET
    url: "{{book.url}}"

  fields:
    title: "h1"
    author: ".author"
    intro: ".intro"
    cover: ".cover img@src"

chapters:
  request:
    method: GET
    url: "{{book.url}}"

  result:
    list: ".chapter-list a"

    fields:
      title: "@text"
      url: "@href"

content:
  request:
    method: GET
    url: "{{chapter.url}}"

  body:
    selector: "#content"

  clean:
    remove:
      - "script"
      - "style"
      - ".advert"
```

# 14. HTTP / Network Engine

所有网络访问统一进入 Network Layer。

```text
Source Engine
      ↓
HttpClient
      ↓
Cache
      ↓
RateLimiter
      ↓
Retry
      ↓
Network
```

统一处理：

```text
timeout
retry
redirect
cookies
headers
proxy
compression
status code
logging
cache
rate limit
```

推荐接口：

```python
class HttpClient:
    async def get(...): ...
    async def post(...): ...
```

Source 不直接依赖具体 HTTP 库。

---

# 15. Rate Limit

必须支持按 Source 隔离限速。

例如：

```yaml
network:
  concurrency: 2
  request_interval_ms: 500
```

不能让多个来源共用一个全局限制器。

原因：

```text
Source A → 2 concurrent
Source B → 5 concurrent
```

互不影响。

# 19. 失败重试

重试不是无限重试。

建议区分：

```text
Network Error
429
5xx
Timeout
Parser Error
Source Error
Validation Error
```

其中：

```text
Network / Timeout / 5xx
→ 自动重试

Parser Error
→ 不建议自动无限重试

Schema Error
→ 立即失败
```

使用指数退避：

```text
1s
2s
4s
8s
...
```

同时增加随机抖动。

# 22. 内容验证

下载成功不代表内容正确。

必须进行基本验证：

```text
正文为空
正文长度异常
内容只剩广告
章节标题异常

```

例如：

```python
if len(content.strip()) < 50:

```

阈值不应该写死在业务代码里，最好提供可配置策略。

# 25. Repository Pattern

业务层不要直接写 SQL。

例如：

```python
class BookRepository(Protocol):
    async def get(self, book_id: str) -> Book | None: ...
    async def save(self, book: Book) -> None: ...
    async def list(self) -> list[Book]: ...
```

实际实现：

```text
BookRepository
      ↓
SQLiteBookRepository
```

以后如果迁移数据库，不需要重写整个业务层。

# 40. 安全设计

MoGrab 本身涉及：

```text
第三方网络资源
第三方 Source
Cookies
可能的登录凭据
```

因此必须做到：

1. Source 默认不能执行任意代码。
2. 默认只监听 localhost。
3. Cookie / Token 不写入普通日志。
4. 日志对 Authorization / Cookie 脱敏。
5. Source 可以声明自己的网络权限。
6. 下载目录路径需要规范化，避免路径穿越。
7. 导出路径必须检查非法文件名。
8. 外部 URL 必须进行合理校验。

最重要的架构决策可以概括为一句话：

> **MoGrab 不追求兼容所有书源，而是建立一套自己的、干净的、稳定的 Source Specification，并围绕这套规范建立 Source Engine、Task Engine 和 API。**

这样能够最大程度避免项目陷入“历史书源兼容地狱”，同时给后续 CLI、Desktop、Source Registry 和社区贡献留下足够空间。



# 57. Build & Release

MoGrab 使用 **GitHub Actions** 完成构建、测试、打包和 GitHub Release 发布。

## 57.1 uv 的职责

`uv` 只属于开发与构建工具链，不作为最终用户运行时依赖。

```text
开发 / CI
    ↓
Python + uv
    ↓
uv sync --locked
    ↓
Lint / Type Check / Test
    ↓
Build
    ↓
Package
    ↓
Release
```

最终发布包中：

```text
uv ❌
开发环境 ❌
```

最终用户不需要自行安装：

```text
Python
uv
Node.js
npm
```

## 57.2 Windows CLI

CLI 使用 **ZIP 分发**，但不要求打包成单个 EXE。

推荐采用目录型构建产物：

```text
MoGrab-CLI-v0.1.0-win-x64.zip
└── MoGrab-CLI/
    ├── mog.exe
    ├── _internal/
    ├── runtime/
    └── ...
```

其中 `mog.exe` 是 CLI 启动入口，Python 运行环境、依赖库和必要原生组件均随目录一起发布。

推荐优先采用：

```text
PyInstaller onedir
```

或其他等价的目录型打包方式。

原则：

```text
✓ 用户无需安装 Python
✓ 用户无需安装 uv
✓ 用户解压后即可运行
✓ CLI 可以包含多个运行时文件
✗ 不要求单文件 EXE
```

不把“单文件”作为产品目标，优先保证：

```text
启动稳定性
依赖完整性
升级便利性
体积可接受
```

## 57.4 用户数据与程序文件分离

程序文件：

```text
Program Files/MoGrab/
```

用户数据：

```text

```

用户数据包括：

```text
config.toml
mograb.db
sources/
cache/
logs/
exports/
```

升级程序时不能删除用户数据库、书源和缓存配置。
