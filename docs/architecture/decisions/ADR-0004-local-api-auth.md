# ADR-0004　本地 API 的鉴权方式

> 状态：已接受
> 日期：2026-10-04
> 关联：规划书 §40、§50；评估报告 P2-02

---

## 背景

规划书 §50 写的是「第一版不需要复杂认证」，§40 要求「默认仅监听
`127.0.0.1`」。当时的判断是：只监听回环地址，就等于只有本机能访问，
所以不着急做认证。

**这个判断是错的。** 「监听回环」和「只有可信调用方能访问」是两件事：

浏览器里的**任意网页**都能向 `127.0.0.1:48721` 发请求。而且下面这类请求
连 CORS 预检都不触发（规范里叫「简单请求」）：

```http
POST /api/v1/tasks HTTP/1.1
Content-Type: text/plain

{"type":"download_book","source_id":"x","url":"https://..."}
```

CORS 约束的是**能不能读到响应**，不是**请求会不会送达**。所以用户随手打开
一个恶意网页，那个页面就能让 MoGrab 开始下载、删书源、建导出任务 ——
哪怕它读不到任何响应内容。

这还不算 DNS rebinding（把某个域名解析到 `127.0.0.1`）那类玩法。

结论：**回环地址不构成信任边界**，必须有凭据。

---

## 选项

### 凭据怎么传

| 选项 | 优点 | 缺点 |
|------|------|------|
| **`Authorization: Bearer <token>`** | 标准；非 CORS 安全列表头，天然挡住简单请求；不会进 URL | `EventSource` 设不了请求头，SSE 需要改客户端 |
| 查询参数 `?token=` | `EventSource` 能用 | **令牌会进访问日志**（uvicorn 记录完整 path），日志会被翻、会被贴 |
| Cookie | 浏览器自动携带 | 渲染层是 `file://` 来源，域规则别扭；自动携带等于放弃 CSRF 防线 |
| 自定义头 `X-MoGrab-Token` | 同样挡住简单请求 | 非标准；OpenAPI 里表达不了，Swagger UI 用不了 |

### 令牌存哪

| 选项 | 优点 | 缺点 |
|------|------|------|
| `config.toml` 的 `[server] token` | 一个文件看全 | 配置文件会被备份、被贴进 issue、在机器之间拷贝 —— 密钥会跟着走；schema 是 `extra="forbid"`，塞机器管理的字段进去让「手改配置」更容易出错 |
| **独立的 `data/token` 文件** | 可单独设 0600；配置文件仍可随意共享 | 多一个文件要认识 |

### 谁生成

| 选项 | 优点 | 缺点 |
|------|------|------|
| 启动时生成，每次重启换新的 | 泄漏窗口小 | 重启后已连接的客户端全部失效；CLI 和 Desktop 要重新握手 |
| **首次生成后持久化，之后复用** | 重启不打断；CLI 与 Desktop 各自读同一份，不依赖启动顺序 | 文件在，令牌就在 |
| 由 Desktop 生成并通过环境变量传给后端 | 桌面端立刻知道 | CLI 拿不到 —— `mog task pause` 会 401 |

---

## 决策

**`Authorization: Bearer <token>`，令牌持久化在 `data/token`（POSIX 0600），
首次使用时生成。**

拆开说：

1. **只认 `Authorization` 头一种方式。** 不做查询参数那条路 —— 令牌出现在
   访问日志里是实打实的泄漏，而日志是最容易被复制出去的东西。代价是
   Desktop 的 SSE 要从 `EventSource` 换成 fetch 流式读取（`sse.ts`）。
   这个代价可以接受：一个鉴权机制比两个好维护，也不会有人误用错的那个。

2. **令牌不进 `config.toml`。** 配置文件是给人看的，令牌是给机器看的，
   两者混在一起迟早出事（用户清空配置、把配置贴到 issue、把配置同步到另一台机器）。

3. **持久化而不是每次启动换新。** 单机场景下，重启就作废会让 CLI 和
   Desktop 频繁需要重新握手，收益却很小 —— 能读到 `data/token` 的攻击者
   本来就能读数据库。

4. **生成在「数据目录解析」这一层，不放 API 层。** CLI 和 Desktop 都要用，
   所以它属于 `mograb.config`，不属于 `mograb_api`。

5. **`/health`、`/docs`、`/openapi.json` 不要求令牌。** `/health` 是探活的
   （Desktop 探端口、`mog server status`），只暴露「在跑」和版本号；
   `/docs` 在浏览器里打开没法带请求头，而接口本身是公开文档。

### 实施细节

- 生成：`secrets.token_urlsafe(32)`，256 位熵，43 个 URL 安全字符。
  用 `secrets` 不用 `random`。
- 比较：`secrets.compare_digest`，不用 `==`。后者比较到第一个不同字符就返回，
  耗时随前缀匹配长度变化。
- 错误：统一返回 401 + `WWW-Authenticate: Bearer`，走既有的
  `{code, message, details}` 模型，错误码 `AUTH_REQUIRED`。
  **不区分「没带令牌」和「令牌不对」** —— 区分了等于告诉对方猜的方向是对的。
- 并发：用 `O_CREAT | O_EXCL` 独占创建来仲裁，谁先创建成功谁的令牌生效。
  *不用*「写临时文件再原子替换」：Windows 上 `os.replace` 遇到目标文件被
  另一个句柄打开时会直接抛 PermissionError，而并发读在这里是常态。
- 开关：`[server] auth = true`。默认开。关掉只在临时调试时说得通 ——
  **监听回环不构成关闭它的理由**。

## 后果

### 正面

- 简单请求那条 CSRF 路径被堵死：它们带不了 `Authorization` 头，直接 401
- 令牌不出现在任何 URL、日志或配置文件里
- CLI 和 Desktop 无需握手，各自读 `data/token` 即可
- OpenAPI 里能正确表达安全方案，Swagger UI 可以直接填令牌调试

### 负面

- **Desktop 的 SSE 不能再依赖浏览器自动重连**，得自己实现（已做，见
  `apps/desktop/src/renderer/sse.ts`，含 4xx 不重连的处理）
- 多了一个需要用户理解的文件（`data/token`）。缓解：正常使用完全不用碰它，
  只有手工 curl 时才需要 `mog server token`
- 令牌在磁盘上是明文。**这是有意的** —— 同目录下就有数据库和书源，
  能读到令牌的攻击者早就能读到别的东西。加密存储只会带来虚假的安全感

### 需要跟进

1. **`mog server token` 的输出可能被误贴到公开场合。** 命令里已经带了提醒，
   但没有强制措施。
2. **令牌轮换没有实现。** 当前只有「删掉文件重新生成」这一种方式，
   且需要重启 server。等真有需求再说。
3. **Electron 的 `file://` 来源在 CORS 预检里可能写作 `null`。**
   已把 `null` 加进允许列表（`allow_origin_regex`）。实测当前版本不发预检，
   但换个 Electron 版本就可能发。
